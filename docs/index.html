Colour

Components use semantic roles only. Values below are read live from tokens.json for the selected theme; each text role shows its contrast against bg.

Do

  • Use text-muted for metadata; it passes 4.5:1 on bg and bg-subtle.
  • Pair colour with text or shape (badges have a label and a dot).

Don't

  • Reference --lm-palette-* in components.
  • Use accent for body text on dark themes without checking contrast.

Typography

Seven roles. Visual role is independent of heading level: an h2 can wear .lm-display.

.lm-display

Only the people read it.

.lm-title

Decide what people see.

.lm-heading

A name, not a number.

.lm-lead

Lead paragraphs introduce a section in one or two sentences.

body

Body text is 16px with a 1.6 line height and a measure around 65 characters in .lm-prose.

.lm-caption

Captions and help text, 14px.

.lm-label

Eyebrow label · 11px

.lm-tabular

1,204 · 98.6 · 0:42

Rules

  • One display per page; titles per section; at most three roles in one block.
  • Fluid sizes use clamp() with px bounds mixed with vw, so browser zoom still scales text.
  • Use .lm-tabular for numbers that change or align.

Don't

  • Skip heading levels to get a smaller look; pick the role class instead.
  • Use .lm-label for anything longer than a few words (uppercase hurts reading).

Spacing

A 4px-based scale. Small steps inside components, large steps between groups: related things sit closer than unrelated ones.

Who owns the space

  • Components own their padding.
  • Layout primitives own the gap between children (--lm-stack-gap, --lm-grid-gap).
  • Sections own page rhythm (--lm-space-section).

Typical pairs

  • Icon to label: space-2 (8px)
  • Label to input: space-2
  • Related fields: space-5 (24px)
  • Heading to its content: space-head-gap (32 to 56px)

Containers

  • .lm-container: max 1200px, gutter 16 to 32px.
  • .lm-prose: about 65 characters per line.
  • .lm-shell: header / main / footer with the footer kept at the bottom.

Breakpoints

  • 520 compact · 760 narrow · 900 medium · 1100 wide.
  • CSS can't read custom properties in @media; import @larkmoor/design-system/breakpoints in JS or scss/breakpoints in Sass.

Motion

Durations

  • fast 150ms: colour and border feedback
  • base 250ms: small movement, toggles
  • slow 400ms: disclosure, sliding thumbs
  • slower 600ms: entrances only

Rules

  • One standard easing: cubic-bezier(.22, .8, .2, 1).
  • Reduced motion shortens every transition to near zero; nothing waits on an animation.
  • Anything that loops over 5 seconds needs a motion toggle.

Button

Triggers an action. Variants: primary (one per view), secondary, danger. Sizes: default 44px, small 36px.

States: hover · focus-visible · busy · unavailable (aria-disabled) · long label

Accessibility

  • Native <button>; Enter and Space activate.
  • Busy and unavailable use aria-disabled so focus is never lost; ignore clicks in script.
  • Icon-only buttons need aria-label; icons get aria-hidden.
  • Minimum 36px tall (above the 24px AA target), 44px for primary touch actions.

Do

  • Name the result: "Request card", not "Submit".
  • Announce the outcome after the work finishes.

Don't

  • Use a button to navigate; use a link.
  • Put two primary buttons side by side.

Link

Take the tourInside prose, links are underlined text.

Rules

  • .lm-link for standalone links next to buttons; prose links stay underlined.
  • Link text says where it goes; never "click here".

Header and navigation

Fixed header with a wordmark, primary nav and one call to action. Below 900px the nav moves into a disclosure menu. See it live on both example sites.

<header class="lm-header" id="header">
  <div class="lm-container lm-header__bar">
    <a class="lm-wordmark" href="#main">…</a>
    <nav class="lm-nav" aria-label="Main"><a href="#a">A</a>…</nav>
    <div class="lm-header__end">
      <a class="lm-btn lm-btn--primary lm-btn--sm" href="#join">Join</a>
      <button class="lm-menu-button" type="button" aria-expanded="false" aria-controls="mobile-menu" aria-label="Open menu"><span></span><span></span></button>
    </div>
  </div>
  <nav class="lm-mobile-menu" id="mobile-menu" aria-label="Mobile" hidden>…</nav>
</header>
<script type="module">
  import { initDisclosureMenu, initHeader } from '@larkmoor/design-system';
  initDisclosureMenu(document.querySelector('.lm-menu-button'));
  initHeader(document.getElementById('header'));
</script>

Keyboard and focus

  • Menu button follows the APG disclosure pattern: aria-expanded, aria-controls.
  • Escape closes the menu and returns focus to the button; picking a link closes it.
  • The header slides back whenever anything inside it gets focus, so focus is never hidden under it.
  • scroll-padding-top keeps anchored headings clear of the header.

Don't

  • Hide the header on scroll when reduced motion is on (the behaviour already skips it).
  • Put more than six items in the main nav.

Segmented control

Density

Accessibility

  • A real radio group in a fieldset with a legend (can be visually hidden).
  • Tab enters the group; arrow keys move and select (APG radio group).
  • In forced colours the selected option uses the system Highlight colour.

Do

  • 2 to 5 short options that change a view immediately.
  • Set --_n to the option count.

Don't

  • Use it for actions or navigation between pages.

Accordion

Open by default

Native details and summary: Enter or Space toggles, and screen readers announce expanded or collapsed.

A long question that wraps across two lines on a phone to show the plus sign stays aligned with the first line

The marker sits on the first baseline.

Rules

  • For optional detail people can skip; never hide required steps.
  • Height animates where ::details-content is supported; elsewhere it opens instantly.

Form field

Shown before the input so it's read first.

Postcodes are 5 to 8 letters and numbers

We deliver there.

Please fix these before sending

  • Postcodes are 5 to 8 letters and numbers

Accessibility

  • Labels are always visible; placeholders are examples, never labels.
  • Hint and message are linked with aria-describedby; errors set aria-invalid and show an icon as well as colour.
  • Inputs are 16px so iOS doesn't zoom on focus.
  • Use type, inputmode and autocomplete for the right keyboard and autofill.

Validation (initForm)

  • Validate on submit; afterwards a wrong field re-checks as you type, so its error clears once fixed. Nothing changes on blur, so the layout never shifts under the pointer.
  • On failure: summary gets focus, each item links to its field.
  • Input is kept on failure; success shows only after the request resolves.

Don't

  • Validate while the person is still typing their first attempt.
  • Disable the submit button to signal errors.

Input group

Rules

  • One input and one action. The focus ring wraps the whole group (also in forced colours).
  • Needs a label, even if visually hidden.

Footer

Brand block plus up to three link columns: four tracks from 900px, three below 900px (brand on its own row), two below 520px. Usually paired with a dark theme via data-lm-theme. Live on both examples.

Motion toggle

↻

Accessibility

  • Toggle button with aria-pressed; satisfies WCAG 2.2.2 for anything that moves longer than 5 seconds.
  • Pausing freezes CSS animations site-wide and fires lm:motionchange for canvas or JS animation.
  • Hidden without JavaScript, because it would do nothing.

Behaviours (JavaScript)

Optional ES modules with TypeScript types. Every function accepts missing markup and returns a cleanup function.

import { initMotionToggle, initDisclosureMenu, initHeader, initReveal, initForm,
         prefersReducedMotion, isMotionPaused, motionOff } from '@larkmoor/design-system';
import { breakpoints, below } from '@larkmoor/design-system/breakpoints';

matchMedia(below('medium')).matches;   // true under 900px
